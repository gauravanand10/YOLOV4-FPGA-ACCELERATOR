# 07_sw/board — ZCU104 application (`yolo_server`)

User-space program for PetaLinux. It needs no kernel driver: it maps the accelerator registers and
the reserved DDR region through `/dev/mem`.

## Files
| File | Role |
|---|---|
| `yolo_accel.h/.c` | **Driver.** `accel_open` (maps regs at 0xA000_0000 and 256 MiB at 0x7000_0000 with `O_SYNC`, checks ID = 0x594F4C34), `accel_load_model` (copies `yolo_desc.bin` + `yolo_weights.bin` into DDR and builds a second descriptor table for input slot 1), `accel_write_input` (RGB → `pixel>>1`, 16-channel HWC), `accel_run` (start, poll done, read counters), `accel_read_heads`, and 64-bit aligned `dev_write`/`dev_read` (unaligned access to device memory faults). |
| `yolo_post.h/.c` | Head decode (sigmoid, `scale_x_y = 1.05`, anchors) + greedy per-class NMS (IoU 0.45). A C port of `02_golden_model/yolo_decode.py`. |
| `yolo_server.c` | TCP server, self-test, and a host-only `--decode` mode. |
| `model_params.h` | Generated by `03_quant_export` (DDR offsets, head scales, anchors, classes); do not edit. |
| `Makefile` | `make CROSS=aarch64-linux-gnu-` (PetaLinux SDK) · `make deploy` · `make host` |
| `build_board.bat` | Windows build with the Vitis 2024.1 aarch64-linux gcc → `deploy/` |
| `deploy/` | **Copy this folder to the board:** `yolo_server` (aarch64 ELF), `yolo_desc.bin`, `yolo_weights.bin`, `test_input_rgb.bin`, `test_heads.bin`, `test_dets.txt` |
| `yolo_decode_host.exe`, `host_dets.txt` | PC build of the decode path, and its output (equals `test_dets.txt`) |

## Memory use (inside the 256 MiB reserved region)
* Model, buffers and input slot 0 take 0x0000_0000–0x00E7_8000 (14.5 MiB).
* Descriptor table for slot 1 at +0x800.
* Input slot 1 at the first free page after the model.
* The accelerator's HP0 port is **not cache coherent**, so all accesses go through the non-cached `/dev/mem` mapping.

## Usage (on the board)
```sh
./yolo_server --selftest .          # bit-exact check of both input slots + accelerator timing
./yolo_server -p 5000 -m . -t 0.25  # detection server (port, model dir, score threshold)
./yolo_server --decode test_heads.bin   # decode only (also works on the PC build)
```
Expected self-test output: `PASS` for slot 0 and slot 1 (INT8 heads identical to the golden model),
about 7.5 M cycles ≈ 40 ms ≈ 25 fps at 187.5 MHz, then a 50-run back-to-back throughput figure.
`ACCEL_CLK_HZ` (default 187,500,000) converts cycles to ms.

## Protocol (TCP, little-endian)
```
client → server : u32 'YOLF' (0x464C4F59), u32 frame_id, u32 w=416, u32 h=416, w·h·3 bytes RGB
server → client : u32 'YOLR' (0x524C4F59), u32 frame_id, u32 ndet, f32 accel_ms, f32 server_ms,
                  ndet × { f32 x1, y1, x2, y2 (normalised 0..1), f32 score, i32 cls }
```
A receiver thread reads and preprocesses frame k+1 into the free input slot while the accelerator
works on frame k (two slots, two descriptor tables). Network transfer and preprocessing therefore
overlap compute.
